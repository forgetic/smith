## Contract and ownership

`None` is canonical absence; a present workspace has one or more directories.
Each has a unique safe component name and unique root token, host write
permission, git kind and initial conflict paths. Plain directories have no
conflicts. Read-only git conflict metadata is informative and grants no writes.
Without a workspace, workspace tool families are suppressed; host tools,
finish, wait and granted sub-agents retain their independent contracts. Change
or delivery without a writable directory refuses before effects.

Count and length checks precede combined Charter/Workspace aggregate ownership
and pairwise semantic checks. Aggregate `run_bytes` includes directory cells,
names, conflict Box cells and path payloads. Initial paths use the existing
relative marker spelling and at most 4,096 bytes; bounds and duplicates refuse
before discovery/provider/tool effects. Configured receiving bounds must agree
with construction. Root receiving limits also fit tools mount/name capacity.

Main and children receive the same optional workspace and kind/conflict prompt
metadata. Queued opening copies, rendered metadata and authority translation
owners are separately priced with checked arithmetic. Root forwards the
original workspace into the run; session authority consumes copied names, roots
and permissions, without becoming a git-policy owner. Caller Start ownership
and concrete handoffs remain separate from component state.

The host kit preserves git metadata through the actual Start Send, validates
workspace/mount presence, names and relative paths, and accepts read-only git
conflicts without widening permissions. Its actual process, call, delivery and
ACK rights remain unchanged; charter and transcript stay opaque.
